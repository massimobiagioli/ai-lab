## context

Every WP-00 task and deliverable is complete and verified. Four items remained open: branch protection application (B-01), the separation-of-duties integration test (B-02), the live metrics dashboard (B-03) and independent review (B-04). B-04 is now resolved by the independent review in `docs/evidence/WP-00-review.md`. B-01, B-02 and B-03 are not WP-00 implementation gaps: they are an environment operation and two downstream WP responsibilities. Keeping WP-00 in `progress` blocks the critical path without increasing evidence.

## proposed_change

1. Accept `.github/branch-protection.json` and `.github/required-checks.txt` as the WP-00 evidence for gate enforcement. Applying protection is a deployment prerequisite performed with the documented `gh api` command; it is not a WP-00 code deliverable.
2. Accept AC7 as a cross-WP contract: WP-00 defines the rule and the `SEPARATION_OF_DUTIES` error; WP-09/WP-15 own the executable integration test.
3. Assign the live dashboard to WP-20. WP-00 delivers the verified views and formulas in `migrations/0002_analytics_views.sql` and `docs/metrics.md`.
4. Record the independent review as the Tech Lead and QA review required by the WP DoD.
5. Do not create additional follow-up cards. The retrospective actions AIL-101..AIL-103 already cover the deployment and toolchain follow-through.

## impact_scope

- WP-00 status becomes `done`.
- No product code, schema, contract or scope change.
- WP-01 becomes eligible immediately.

## impact_schedule

WP-01 unblocked on 2026-11-07.

## impact_cost

## impact_risk

High-impact risk: branch protection is not enforced until deployment. Mitigated by the exact required-context list, the apply command, and the existing retrospective action AIL-101. AC7 evidence arrives with WP-09/WP-15; the rule is already normative. The dashboard arrives with WP-20; the views are verified against fixtures.

## alternatives

1. Keep WP-00 in `progress` until a remote and WP-09/WP-15 exist. Rejected: blocks the critical path with no new WP-00 evidence.
2. Create new follow-up cards for each item. Rejected by the Human Operator: duplicates existing WPs and retro actions.
3. Mark the items evidenced without a decision. Rejected: violates the evidence rule.

## decision

`approved`. WP-00 is closed as `done`; B-01, B-02 and B-03 are assigned to deployment, WP-09/WP-15 and WP-20 respectively; B-04 is resolved by the independent review.
