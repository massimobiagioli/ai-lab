## B.1 OpenAPI 3.1 — REST surface

### B.1.1 Conventions

- Base URL: `http://{host}:{port}/api/v1`
- Content type: `application/json; charset=utf-8`
- All timestamps: RFC 3339 UTC (`2026-11-07T10:00:00Z`)
- IDs: UUIDv7 strings
- Money in API responses: `{"amount_microusd": 1234567, "amount_usd": "1.234567"}` (both fields; integer is authoritative)
- Pagination: `?limit=50&cursor=<opaque>`; response `{"data":[...],"next_cursor":"...","total_estimate":123}`
- Filtering: `?filter[column]=DOING&filter[assignee_id]=...&sort=-updated_at`
- Idempotency: `Idempotency-Key` header required on creating POSTs with side effects.
- Correlation: `X-Request-Id` echoed; `traceparent` accepted.
- Errors: RFC 9457 `application/problem+json` with AI-Lab `code` and optional `violations[]`.

### B.1.2 Security schemes

```yaml
components:
  securitySchemes:
    BearerAuth:
      type: http
      scheme: bearer
      bearerFormat: opaque
# Applied to all paths except /health/live when AILAB_BIND != loopback.
```

### B.1.5 Status and error codes

| HTTP | `code` | Meaning |
|---|---|---|
| 400 | `BAD_REQUEST` | Malformed JSON or query |
| 401 | `UNAUTHORIZED` | Missing/invalid bearer token (remote mode) |
| 403 | `FORBIDDEN` | Policy/actor not allowed |
| 404 | `NOT_FOUND` | Resource missing |
| 409 | `VERSION_CONFLICT` | Optimistic concurrency failure |
| 409 | `ALREADY_LEASED` | Card already claimed |
| 422 | `VALIDATION_FAILED` | Schema/field validation |
| 422 | `INVALID_TRANSITION` | Kanban transition not allowed |
| 422 | `DOR_INCOMPLETE` | Definition of Ready unmet |
| 422 | `DOD_INCOMPLETE` | Definition of Done unmet |
| 422 | `SEPARATION_OF_DUTIES` | Reviewer/merger conflict |
| 422 | `WIP_LIMIT_EXCEEDED` | Column/agent WIP limit |
| 422 | `BUDGET_EXCEEDED` | Card/lab budget |
| 429 | `RATE_LIMITED` | Slow down; see `Retry-After` |
| 500 | `INTERNAL` | Unexpected; trace_id provided |
| 502 | `PROVIDER_UNAVAILABLE` | LLM/SCM upstream failure |
| 503 | `NOT_READY` | Dependency unavailable |
| 504 | `UPSTREAM_TIMEOUT` | LLM/SCM timeout |

### B.2.4 Ordering and replay

- `seq` is strictly increasing per lab and assigned inside the transaction that writes the domain event.
- Clients MUST apply events idempotently by `event_id` and ignore `seq <= last_applied`.
- Gaps on reconnect: `GET /events?lab_id=...&after=<last_seq>&limit=1000`, loop until caught up, then resubscribe.
- Ephemeral events (`office.agent.speech`, typing) have no `seq`; they MUST NOT be replayed.

## B.4 Webhook contract (GitHub)

- Header `X-Hub-Signature-256: sha256=<hex>` HMAC of raw body with the webhook secret.
- Idempotency: `X-GitHub-Delivery` is the primary key in `github_webhook_deliveries`.
- Accepted events: `pull_request`, `check_run`, `push`, `pull_request_review`.
- Reject: invalid signature (401), unknown repo (404), archived project (410), replay outside 5 min (409).
- Response: `202` immediately; processing is asynchronous.
