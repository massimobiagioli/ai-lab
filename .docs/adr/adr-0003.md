# ADR-0003 — PostgreSQL as the sole durable system of record

## Context

The domain needs durable, queryable, transactional state with vectors, full-text search and audit. Using multiple stores as sources of truth would create reconciliation problems.

## Decision

Use PostgreSQL 18 with pgvector as the only durable system of record. Redis is cache, rate-limit, lock and ephemeral pub/sub storage only and is never authoritative.

## Consequences

One backup, one migration path, strong consistency and simple recovery. PostgreSQL becomes the scaling bottleneck; vertical scaling and read replicas are the documented path.

## Alternatives considered

Event store plus separate relational and vector databases. Rejected for v1 due to operational complexity and cross-store consistency.
