# ADR-0002 — Modular monolith with bounded contexts

## Context

AI-Lab needs clear domain boundaries but must remain operable by one person. A distributed microservice mesh would add network failures, distributed transactions and operational overhead without product value in v1.

## Decision

Deploy a modular monolith as a small set of runtime services (`web`, `api`, `worker`, `runner`, `migrate`) with five bounded contexts and contract-first boundaries. No context reads or writes another context's tables.

## Consequences

Strong transactional consistency, simple operations and fast delivery. Contexts can be extracted later without changing consumers because contracts and data ownership are explicit.

## Alternatives considered

Independent microservice per context. Rejected for v1 due to operational cost and distributed consistency. Revisit through a new ADR if scale or team topology requires it.

## Status

Accepted on 2026-11-07 by Tech Lead, QA.
