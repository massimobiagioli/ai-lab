# ADR-0022 — Version pinning, Renovate, SBOM and no EOL dependencies

## Context

Floating versions and EOL runtimes create security and reproducibility risk.

## Decision

Pin all toolchains and images, commit lockfiles, run Renovate weekly, enforce `cargo-deny` and `npm audit`, generate SBOMs and sign images. No EOL lines are allowed.

## Consequences

Reproducible builds and a controlled upgrade path. Upgrades require regular attention and ADRs for majors.

## Alternatives considered

Floating versions with ad-hoc upgrades. Rejected because it breaks reproducibility and security response.

## Status

Accepted on 2026-11-07 by Tech Lead, QA.
