# ADR-0004 — Transactional outbox with SKIP LOCKED instead of a broker

## Context

Publishing domain events must be atomic with the state change, and the product must remain operable without an additional broker.

## Decision

Write domain events to an outbox in the same database transaction, relay them at-least-once to Redis and WebSocket clients, and use `FOR UPDATE SKIP LOCKED` for worker leasing. Consumers are idempotent by `event_id`.

## Consequences

No dual-write problem, no broker to operate, and crash recovery is straightforward. The outbox relay must be monitored; event ordering is per aggregate with a per-lab sequence.

## Alternatives considered

Kafka, RabbitMQ or NATS. Rejected for v1 due to operational burden and the absence of a need for cross-datacenter streaming.

## Status

Accepted on 2026-11-07 by Tech Lead, QA.
