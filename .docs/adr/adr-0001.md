## Context

The product spans a Rust backend, an Angular frontend, shared contracts, migrations and infrastructure. Split repositories would add version skew and coordination cost for a single-operator product.

## Decision

Keep one monorepo with a Cargo workspace, an Angular workspace, shared docs, migrations and infrastructure. Build and release independently per artifact but version them together.

## Consequences

Simpler dependency management, atomic contract changes and one source of truth. The repository grows; CI must use path filters and caching to stay fast.

## Alternatives considered

Polyrepo with a package registry. Rejected because contract drift and cross-repo release coordination outweigh isolation benefits.

Accepted on 2026-11-07 by Tech Lead, QA.
