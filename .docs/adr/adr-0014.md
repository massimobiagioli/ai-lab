# ADR-0014 — WebSocket with resumable sequence and event backfill

## Context

The UI must receive ordered, replayable domain events without losing state on reconnect.

## Decision

Use a single WebSocket per client with topic subscriptions, a per-lab monotonic `seq`, replay from `domain_events` on connect and a REST backfill endpoint for gaps beyond the buffer.

## Consequences

Ordered, resumable real-time updates. Clients must implement deduplication and gap handling; ephemeral events are lossy by design.

## Alternatives considered

Server-Sent Events only or polling. Rejected because bidirectional subscriptions and backpressure are needed.
