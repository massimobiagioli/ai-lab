## Story

As a QA engineer,
I want every required CI job to run its real command unconditionally,
so that a missing manifest cannot make a required check pass without doing work.

### Context

WP-00 delivered the CI workflow with named jobs. Jobs whose toolchain does not exist yet guard on the manifest and exit 0 with an explicit message. This card removes those guards once WP-02 lands the workspace and WP-17 lands the Angular app.

## Acceptance criteria

Given the Rust workspace and Angular app exist
When a pull request runs CI
Then `fmt`, `clippy`, `rust-unit`, `rust-integration`, `frontend-lint`, `frontend-unit` and `frontend-build` run their real commands
And no job exits early because a manifest is absent.

## Deliverables

- `.github/workflows/ci.yml` — guards removed; `security-deps` runs both scanners unconditionally.
- `.docs/product/quality-gates.md` §9 — bootstrap note removed.
- A CI run URL showing all checks executed.

## Out of scope

- Adding new gates.
- Changing thresholds.

## Risks / dependencies

- Removing a guard before the toolchain exists turns the default branch red. Sequence the merge after the manifests land.
