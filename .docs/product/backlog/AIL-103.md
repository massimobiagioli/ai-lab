## Story

As the Tech Lead,
I want each run to store the autonomy level it executed under,
so that the autonomous-success metric is exact instead of using the agent's current value.

### Context

`analytics.autonomous_success` currently reads `agents.autonomy_level`, which is the current value and not a snapshot at run time. A later autonomy change rewrites history. The metric is documented as experimental until this card lands.

## Acceptance criteria

Given a run executes under autonomy A2
When the run is persisted
Then the autonomy level used is stored on the run
And `analytics.autonomous_success` reads the stored value
And changing the agent's autonomy later does not change historical metrics.

## Deliverables

- `migrations/<timestamp>_add_run_autonomy.sql` — additive nullable column with a backfill plan.
- `analytics.autonomous_success` — reads the stored value.
- Integration test proving that a later agent change does not alter historical attribution.
- `.docs/product/metrics.md` §3.8 — limitation removed.

## Out of scope

- Changing autonomy defaults.
- Backfilling old runs with a guessed value.

## Risks / dependencies

- Historical runs have no stored value. Treat them as `unknown` and exclude them from the denominator until backfilled from an authoritative source.
