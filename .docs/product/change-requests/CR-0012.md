## context

WP-13 and WP-16 delivered the scheduler, pipeline, runner client, edge server, contracts and the hardening increments recorded in their progress logs. The independent QA still returns `CHANGES_REQUESTED` for a set of large residual items: real context retrieval, open/branch resume, OTel spans/metrics, Kanban-service DoD, production LLM/SCM adapters, Redis rate limiting/fan-out, the full REST operation surface, WebSocket ephemeral backpressure, generated OpenAPI with breaking-change checks and component readiness.

Those items require new subsystems (WP-08 memory/repo providers, WP-20 telemetry export, a real HTTP transport, Redis) and cannot be completed without blocking the frontend milestone. The Tech Lead re-baselines them into a dedicated follow-up work package that is scheduled last.

## proposed_change

1. Create `WP-13B` (`.docs/sow/WP-13B-FOLLOW-UP.md`) containing the residual items as tasks WP13B-T01..T11 with acceptance criteria.
2. Record the deferral in the WP-13 and WP-16 progress logs and status history; close both as `done` with the WP-13B deferral named explicitly.
3. Keep WP-13B `ready` until the frontend work packages complete; it is the final delivery slot.
4. Allow the SOW linter to accept the `WP-13B` identifier.

This is a Tech Lead re-baseline, not a QA approval. The QA `CHANGES_REQUESTED` evidence stays in the WP-13/WP-16 review plans and is carried into WP-13B.

## impact_scope

- `.docs/sow/WP-13B-FOLLOW-UP.md` (new), `.docs/sow/SOW.md`
- `.docs/sow/WP-13-ORCHESTRATION.md`, `.docs/sow/WP-16-API-REALTIME.md`
- `scripts/sow-lint.sh`
- `.docs/product/change-requests/README.md`

## impact_schedule

Unblocks WP-17..WP-19 (frontend); WP-13B runs after WP-23 as the final hardening slot.

## impact_cost

34 points tracked in WP-13B.

## impact_risk

Deferring the residuals keeps the frontend milestone moving but leaves the backend hardening open until WP-13B. The deferral is explicit and traceable, and no item is claimed as delivered.

## alternatives

1. Keep WP-13/WP-16 `progress` until every residual closes. Rejected: blocks WP-17, WP-18 and WP-19, which need the edge contracts but not the residual hardening.
2. Mark the residuals as accepted risk without a follow-up. Rejected: loses traceability.

## decision

`approved`. Create WP-13B, close WP-13/WP-16 with the named deferral, and proceed with WP-17.
