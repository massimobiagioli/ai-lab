# CR-0007 — Add the least-privilege database role passwords to the environment contract

## context

WP-04 §3.1 requires separate least-privilege roles (`ailab_app` DML, `ailab_migrate` DDL, `ailab_readonly` read-only); the application must not connect as the PostgreSQL bootstrap superuser. The roles are created on first initialisation and their passwords must be configurable, but Appendix D.4 (the complete environment contract) did not list them.

## proposed_change

Add three variables to Appendix D.4 and `.env.example`:

- `AILAB_APP_DB_PASSWORD` — password for the application role.
- `AILAB_MIGRATE_DB_PASSWORD` — password for the migration role.
- `AILAB_READONLY_DB_PASSWORD` — password for the read-only role.

Mount `infra/postgres/init-roles.sh` into `/docker-entrypoint-initdb.d/` so a fresh cluster creates the roles; the application DSN uses `ailab_app` and the migrate service uses `ailab_migrate`.

## impact_scope

- `.docs/technical-specification/APPENDIX-D-DELIVERY.md` §D.4
- `.env.example`
- `infra/compose/docker-compose.yml`, `infra/postgres/init-roles.sh`
- WP-04 review evidence

## impact_schedule

None.

## impact_cost

None.

## impact_risk

An existing volume initialised before this change will not contain the roles; `make reset` (or a documented one-off grant) is required. Default passwords are development-only placeholders and must be overridden outside the local profile.

## alternatives

1. Keep the application on the superuser. Rejected: violates least privilege and WP-04 §3.1.
2. Hard-code role passwords in SQL. Rejected: secret in version control.

## decision

`approved`. Add the three variables and the init script.
