# CR-0014 — Reopen WP-18 for the office host build

| Field | Value |
|---|---|
| id | `CR-0014` |
| title | Reopen WP-18 to build the canvas office host on the WP-17 platform |
| decision | `approved` |

| date | 2026-11-07 |
| linked_adr | ADR-0021 |

## context

WP-18 is marked `done`, but only the framework-agnostic A* and agent-state helpers exist; there is no canvas host, no tile map, no interactions and no truthful rendering. The office cannot be demonstrated.

## proposed_change

Reopen WP-18 from `done` to `progress` and deliver the canvas office host: deterministic layout, A* movement, agent selection, click-to-walk, state-driven colours/animation, reduced-motion snapping and an accessible agent list. Remaining sprite atlas, ambient life, sound, FPS telemetry and visual tests stay as follow-up evidence.

## impact_scope

- `.docs/sow/WP-18-VIRTUAL-OFFICE.md`, `.docs/sow/SOW.md`
- `web/src/lib/office/**`, `web/src/app/features/office/**`, `web/src/app/app.routes.ts`
- `.docs/product/office.md`

## impact_schedule

WP-19 (product UI) consumes the office route and panel.

## impact_cost

Layout, engine, canvas renderer, interactions, tests and docs.

## impact_risk

Shipping WP-19 on a missing office is a false product gate.

## alternatives

1. Keep `done` and build the office inside WP-19. Rejected: breaks the WP-18/WP-19 boundary and ADR-0021 (engine decoupled from Angular).
2. Build the office incrementally in WP-18. Accepted.

## decision

`approved`. Reopen WP-18 and deliver the office host.
