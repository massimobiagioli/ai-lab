## context

WP-13 is marked `done`, but the review found that only the scheduler/lease/run-state/retry/budget/reconcile subset exists (`crates/orchestrator/src/orchestration.rs`; `.docs/product/orchestration.md` §8 itself defers the pipeline). The contract marks the 13-stage pipeline, context builder, agent loop, verification loop, PR orchestration, handoff/review/merge, cancellation-to-sandbox, escalation, run APIs/events/metrics and the E2E suites as deliverables, and AC2–AC6, AC8, AC10 and AC11 are unverified. The status is therefore not evidence-backed.

## proposed_change

Reopen WP-13 from `done` to `progress` with `blocked=false` and a recorded blocker list. Deliver the missing pipeline and ACs before re-closing. WP-14..WP-23 consumers that depend on the pipeline remain at risk.

## impact_scope

- `.docs/sow/WP-13-ORCHESTRATION.md` status/history/progress
- `.docs/sow/SOW.md` index row
- `crates/orchestrator` (pipeline implementation)
- WP-14..WP-23 consumers of the run pipeline

## impact_schedule

WP-13 re-enters M5; WP-14..WP-23 verification is paused until the pipeline exists.

## impact_cost

Substantial implementation effort (pipeline, agent loop, verification, PR, handoff, telemetry).

## impact_risk

The program cannot be declared complete on a skeleton orchestrator; hiding the gap would be a false gate.

## alternatives

1. Keep WP-13 `done` with deferrals. Rejected: the WP contract lists the pipeline as in-scope and ACs are unverified.
2. Split the remaining work into a new WP. Rejected: it is the same contract; reopening preserves traceability.

## decision

`approved`. Reopen WP-13 to `progress` and track the gaps in its review plan.
