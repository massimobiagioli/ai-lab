## context

WP-00 acceptance criterion 3 requires the 16 required checks to be enforced by branch protection on the remote default branch. The remote `origin` now exists. The previously prepared configuration required pull-request reviews and linear history, which would block the documented review workflow: one branch per WP, a QA subagent verdict, then a `--no-ff` merge into `main`.

## proposed_change

Apply the branch protection configuration with the 16 required status contexts, keep force-pushes and deletions blocked, and adjust only what blocks the review merge workflow:

- `enforce_admins`: `false` so the reviewing engineer can complete the authorized merge.
- `required_pull_request_reviews`: `null` so the review branch can be merged directly after the independent QA subagent approves it.
- `required_linear_history`: `false` so the `--no-ff` merge commit is accepted.

Separation of duties remains enforced by the application (`crates/application/src/qa.rs`), the PR template, the QA subagent verdict and the WP process.

## impact_scope

- `.github/branch-protection.json`
- Remote branch protection for `main`
- WP-00 acceptance criterion 3 and blocker B-01

## impact_schedule

None. The configuration is applied during the WP-00 review.

## impact_cost

None.

## impact_risk

GitHub-level admin bypass and merge commits are allowed; the application-level separation of duties and the QA review still block self-review and self-merge. Revisit at release with the final operator policy.

## alternatives

1. Require GitHub pull-request reviews and squash merges. Rejected: the review workflow is branch-per-WP with a QA subagent and a `--no-ff` merge; requiring GitHub reviews would duplicate the QA control and block the documented merge.
2. Keep the CR-0002 waiver. Rejected: the remote now exists and the configuration can be applied.
3. Require linear history and use squash merges. Rejected: the review prompt requires an auditable merge commit.

## decision

`approved`. Apply the 16 required contexts; disable enforced admin protection, required PR reviews and linear history only; keep force-pushes and deletions blocked.

## approver

Tech Lead (agent) and Human Operator (instruction 2026-11-07).

## linked_adr

None. The change is reversible and does not change architecture.
