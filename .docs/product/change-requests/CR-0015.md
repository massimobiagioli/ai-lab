## context

WP-19 is marked `done`, but the product routes are placeholders: the dashboard and runs page exist, while the Kanban board, inventory, SOW, memory, settings and onboarding surfaces are not built. The platform (WP-17) and office (WP-18) are now in place.

## proposed_change

Reopen WP-19 from `done` to `progress` and deliver the product surfaces in ordered increments: data layer and stores (P01), Kanban (P02), inventory (P03), SOW (P04), memory (P05), settings/onboarding (P06), then QA (P07). Where the edge endpoints are still 501 stubs, use an explicit, deterministic demo read model flagged `AILAB_DEMO_DATA` and re-run the real-data assertions in WP-13B T07.

## impact_scope

- `.docs/sow/WP-19-PRODUCT-UI.md`, `.docs/sow/WP-19-PRODUCT-UI-review-plan.md`, `.docs/sow/SOW.md`
- `web/src/app/{core,domain,features}/**`, `.docs/product/`

## impact_schedule

WP-20..WP-23 follow; WP-13B T07 closes the real-data gap last.

## impact_cost

Data layer, six surfaces, tests, docs and QA.

## impact_risk

Keeping `done` would misrepresent an unbuilt product UI.

## alternatives

1. Build the surfaces inside WP-20..WP-23. Rejected: breaks the WP boundary and the review order.
2. Build the surfaces incrementally in WP-19. Accepted.

## decision

`approved`. Reopen WP-19 and deliver the surfaces in the P01–P07 increments.
