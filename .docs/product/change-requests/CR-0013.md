## context

WP-17 is marked `done`, but the workspace still contains the Angular starter: an empty router, no API/WS services, no shell, no feature stores and only a status badge in the design system. The product surface cannot be built on this baseline.

## proposed_change

Reopen WP-17 from `done` to `progress` and deliver the core platform: app shell with sidebar/topbar/drawers/toasts, lazy routes, generated-style API client with Problem handling and retries, WebSocket service with reconnect/resume/dedupe/backpressure, signal feature stores, pixel UI primitives, accessibility scaffolding, telemetry and tests.

## impact_scope

- `.docs/sow/WP-17-FRONTEND-PLATFORM.md`, `.docs/sow/SOW.md`
- `web/src/**`, `web/README.md`, `web/e2e/**`
- `.docs/product/frontend.md`

## impact_schedule

WP-18 and WP-19 depend on the platform primitives and routes.

## impact_cost

Shell, core services, stores, UI kit, a11y, tests and docs.

## impact_risk

Shipping WP-18/WP-19 on the starter placeholder would be a false frontend gate.

## alternatives

1. Keep `done` and build primitives inside WP-18/WP-19. Rejected: duplicates the platform and breaks layering.
2. Build the platform incrementally in WP-17. Accepted.

## decision

`approved`. Reopen WP-17 and deliver the platform.
